# 发布准备

当前版本：三个包均为 0.1.0。根 workspace 保持 private，只有三个包是 npm 发布目标。

## 待用户决定

1. 使用哪个 npm 账号；保留当前三个非 scope 名称，还是改成 `@<scope>/dsh-plugin-…`。没有注册 scope，也没有登录操作。
2. 最终许可证与版权主体。当前各包的 `license` 指向包内占位 LICENSE，不代表已经选择开源许可。Grok 复用模块保留了 MIT 来源声明，完整版权通知仍需核对。
3. GitHub 账号 / 组织与远端仓库名；是否公开。当前 repository/homepage 使用 `REPLACE_ME`，没有配置远端。
4. 确定发布范围与 npm access。Changesets 当前按公开包准备；若选择受限包，需先确定 scope 并相应改配置。

若改 scope，须一起修改 package name、两业务包的 peer key、dsh.client.inject / external、各 client.js 的 ModuleLoader id 和来源壳 require、激活 patch、安装器映射检查、Changesets fixed 组与测试。安装器会直接读取包元数据，无需在安装命令中另写 scope。

## 版本管理

使用 Changesets 而不是手工散改三份版本。固定组保证三个包同步递增，来源壳浏览器契约变更可以共同发布。初次整理已直接设为 0.1.0；记录了一份 empty changeset 标注原样导入与发布准备，不安排版本 bump，避免准备时意外升到 0.1.1。

```bash
npm run changeset
npm run changeset -- status
npm run version:packages
```

`version:packages` 会修改版本 / 依赖范围与各包 changelog，需检查并提交。Changesets 的访问级别配置只是准备，不会自动发布。

## 发布前本地复核

```bash
npm ci --ignore-scripts
npm run release:check
npm view dsh-plugin-workbench-sources name version --json
npm view dsh-plugin-herdr-live name version --json
npm view dsh-plugin-grok-workbench name version --json
```

本次查询公共 registry 三个名称都返回 E404，未发现公开同名包；这不保留名称，也不保证将来 npm 会接受首次发布。正式操作前重新查询并确认账号权限。

pack dry-run 检查各包白名单，不能代替许可证和发布账号决定。本仓库的 GitHub Actions 草稿仅检查，无 npm token、自动 publish 或远端创建步骤。

经用户明确确认后才可以运行根脚本 `release:publish`（Changesets），或单独在各包运行 npm publish。本次任务不执行这些命令，不 push，也不创建远端仓库。
