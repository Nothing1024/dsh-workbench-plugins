## 发布前验证

```bash
npm ci --ignore-scripts
npm run release:check
npm run verify:install
npm run changeset -- status
```

本地可给 verify:install 传入 DSH 的 package.json 路径，增加真实 profile 安装与模块加载验证。敏感信息检查覆盖 Git 历史、当前源码和实际 tarball；包内容按白名单检查。

Herdr 端口保存需验证：请求使用旧监听端口，保存成功后才更新浏览器偏好，重启后读取新端口；失败保留原连接和编辑内容。真实 Grok 账号与真实 Ovis 服务仍需在用户环境中确认。

## 生成发布包

```bash
npm pack --pack-destination /发布包目录
```

发布包包含 index.js、src、构建后的 dist/client.js、启用声明、README、CHANGELOG、LICENSE 和第三方说明。不包含开发依赖、测试、脚本、过程记录、.env 或用户账号数据。

## 上传 npm

2026-11-07 的账号检查返回 E401，正式上传前需要重新登录 npm。无需将账号密码或 token 写入仓库。

```bash
npm login --registry=https://registry.npmjs.org/
npm whoami --registry=https://registry.npmjs.org/
npm publish ./dsh-plugin-workbench-suite-0.1.0.tgz --access public --ignore-scripts --registry=https://registry.npmjs.org/
```

上面的发布命令上传已检查过的 tarball。GitHub Actions 只做检查、测试、打包和安装验证，不自动上传 npm。以后修改功能时增加 Changeset，执行 `npm run version:packages` 生成后续版本和 changelog。
