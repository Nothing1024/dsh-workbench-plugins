# 三套插件的安装与契合

此独立仓库从原 `真实接入/packages/` 复制三包；原 `plugin/`、`grok-plugin/`、`*-ui-opt/` 和 `packages/` 均不改动。第一次 Git 提交保留三包原样代码，后续提交记录发布整理。

| 目录 | 包名 | 职责 |
| --- | --- | --- |
| `packages/workbench-sources` | `dsh-plugin-workbench-sources` | 来源栏壳，只注册「DSH 会话」；浏览器模块导出 `SOURCE_TAB_SLOT` / `SourceTab` |
| `packages/herdr-live` | `dsh-plugin-herdr-live` | Ovis / Herdr 侧栏、iframe、proxy / sidebar-channel / embed-bridge |
| `packages/grok-workbench` | `dsh-plugin-grok-workbench` | Grok 对话与 auth，包含 grok-service 和 grok/* |

宿主负责 Logo、新会话、原生导航。来源栏和业务 UI 由插件提供。来源壳没有代理和业务面板；Grok 不 require Herdr。

## 安装组合与来源

```bash
# 本地三包，仅预览命令
node scripts/install.mjs both --source local --profile workbench-demo --dry-run
# 本地执行：可将 both 换成 herdr 或 grok
node scripts/install.mjs both --source local --profile workbench-demo

# npm 来源：包发布后才能执行
node scripts/install.mjs both --source npm --version 0.1.0 --profile workbench-demo --dry-run
node scripts/install.mjs both --source npm --version 0.1.0 --profile workbench-demo
```

- both：来源壳 + Herdr + Grok；herdr：来源壳 + Herdr；grok：来源壳 + Grok。
- `--profile` 必填，脚本不会默认操作 `web` 或其它正在使用的 profile。
- 命令由 argv 数组执行，不交给 shell；参数错误、找不到 dsh、子进程非零退出均会失败。
- local 使用绝对 `file:` URL 指向本仓库内包；npm 使用各包的 `name@version`。同一组合在一条 `add` 命令中安装，来源壳列在前面。
- `--version` 默认读取包版本；环境变量 `DSH_WORKBENCH_PLUGINS_VERSION` 可覆盖默认值。
- `sources` 组合只安装来源壳，供开发使用。
- 安装不会移除已装业务包，切换组合不等于卸载。`*-ui-opt` 需自行从目标 profile 卸载后再装正式组合。

等价的手动本地命令（在仓库根目录执行）：

```bash
dsh plugin --profile workbench-demo add "file:$PWD/packages/workbench-sources" "file:$PWD/packages/herdr-live" "file:$PWD/packages/grok-workbench"
```

等价的 npm 命令（发布后）：

```bash
dsh plugin --profile workbench-demo add dsh-plugin-workbench-sources@0.1.0 dsh-plugin-herdr-live@0.1.0 dsh-plugin-grok-workbench@0.1.0
```

## npm 依赖与 DSH 加载

Herdr / Grok 将来源壳声明为必需 peer：`dsh-plugin-workbench-sources: ^0.1.0`。来源栏是宿主级共享 UI，一个 profile 应只有一个实例。必需 peer 让 npm/pnpm 检查契约兼容性，也避免两业务包各藏一份来源壳。安装器显式加入来源壳：DSH profile 默认关闭自动安装 peer，且安装包和激活插件是两个步骤。

三包均声明 `dsh.bundle.patch: ./cordis.patch.yml`，每份 patch 只插入自己的插件行。安装器同时装入所需包，DSH `plugin add` 将它们作为 profile layers 启用。原代码只有 `dsh.client`，缺少 bundle 时新 DSH 会把包当普通依赖安装，界面不会自动出现；这里补齐了激活声明。

三个包继续导出 `./client`，浏览器 factory 的 id 与 npm 包名一致。`dsh.client.inject` 保留原有布局 / 侧栏 / 设置依赖；另通过 `external` 声明 React、ReactDOM 和业务包使用的来源壳，供客户端依赖图排序。两业务包的 `require` 读取来源壳的浏览器导出，而 Node 的 `index.js` 只提供 host apply。验证必须同时覆盖 Node 包解析、DSH 激活 patch 和 browser factory require。

不要把官方 DSH UI 插件、React 或 ReactDOM 添加为普通运行时 dependencies；它们由当前 DSH 宿主提供。

## 设置

入口：设置 → 内置插件；无对应宿主槽位时，Herdr 标题栏设置按钮 / Grok「更多 → 插件设置」提供插件内面板。

### 工作台来源

显示「DSH 会话」、会话标签顺序。默认顺序 0，Herdr 为 10、Grok 为 20。立即生效，localStorage 键为 `dsh-workbench-sources-prefs`。

### Herdr

- Ovis URL：默认 `http://127.0.0.1:7317`。
- 本地代理：默认 `127.0.0.1:50760`。
- DSH 父页面 origin：默认沿用预览地址 `http://127.0.0.1:50759`，应改为实际页面 origin；例如当前工作台运行在 3080，就填 `http://127.0.0.1:3080`。
- 仅允许本机 HTTP 回环 origin。测试连接、保存应用、重新连接可在设置页操作。

偏好保存在 `~/.dsh/herdr-live/prefs.json`。启动时 `DSH_HERDR_UPSTREAM` / `DSH_HERDR_PARENT_ORIGIN` / `DSH_HERDR_PROXY_PORT` 优先。URL 变更可更新当前代理；端口变更须重启 DSH 才能重新监听。

### Grok bot

检测会话、重新加载会话、打开 grok.com 登录、清除本地会话缓存、查看中继状态。设置页只展示是否登录、来源、用户 id 和 cookie 名称，不展示 cookie 值。

解析顺序：显式插件配置或 `GROK_COOKIE` / `GROK_SSO` → 用户维护的 `~/.dsh/grokbot/cookie.txt` → 已打开且可调试的 Chrome 系浏览器 → 12 小时磁盘缓存。清除缓存不会删除用户维护的 cookie 文件。测试不读取真实 cookie，不连接账号。

## 验证边界

```bash
npm ci --ignore-scripts
npm run check
npm test
npm run pack:dry-run
```

`check` 覆盖仓库内全部 JS / MJS（排除 node_modules 和临时产物），并核对包元数据。离线测试迁自原测试，针对新路径与新来源壳契约适配；服务端 fixture 使用假中继与回环 HTTP 服务。打包检查使用精确 files 白名单并拒绝额外文件。

`npm run verify:install` 会生成本地 tarball，离线安装并检查三种组合的 Node / 浏览器模块解析。可加 `-- --dsh-anchor /绝对路径/@deepseek-ai/dsh/package.json`，用该 DSH CLI 在独立 home 中执行三种本地安装，检查 bundle 激活和真实客户端模块表。

安装与加载 smoke 在独立临时目录进行，不修改在用的 DSH profile。新仓库尚未进行真实 Grok 登录 / 发消息或真实 Ovis UI 交互验收；npm registry 安装要等正式发布，预发布阶段用生成的本地 tarball 检查 node_modules 路径。
