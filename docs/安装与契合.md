# 安装与契合

本仓库发布一个 `dsh-plugin-workbench-suite` 包，默认同时启用 DSH 会话、Herdr 和 Grok。

## 本地安装

在仓库根目录执行：

```bash
npm ci --ignore-scripts
npm run build
node scripts/install.mjs --source local --profile workbench-demo --dry-run
node scripts/install.mjs --source local --profile workbench-demo
```

## npm 安装

正式发布后可执行：

```bash
dsh plugin --profile workbench-demo add dsh-plugin-workbench-suite@0.1.0
```

仓库内安装器的等价用法：

```bash
node scripts/install.mjs --source npm --profile workbench-demo --version 0.1.0 --dry-run
node scripts/install.mjs --source npm --profile workbench-demo --version 0.1.0
```

不再选择 both / herdr / grok 安装组合。只安装一个包，启用声明中也只有一条工作台插件记录。`--profile` 仍为必填，安装后重启对应窗口。

## 加载约定

| 入口 | 内容 |
|---|---|
| `index.js` | 统一的宿主 `apply`；注册 Grok 路由并启动 Herdr 代理 |
| `src/client.js` | 组合来源栏、Herdr 和 Grok 的客户端初始化 |
| `dist/client.js` | 单个 `__ModuleLoader__` factory；由 `./client` 导出 |
| `cordis.patch.yml` | 只插入 `dsh-plugin-workbench-suite` |

客户端通过相对引用使用内部模块；共享来源栏不再是 npm 依赖。`dsh.client.inject` 只声明宿主界面依赖，`external` 为 React 和 ReactDOM。

## 配置与迁移

已有来源偏好、Herdr 接入偏好和 Grok 凭据路径继续使用原有位置。Herdr 父页面地址应设为实际 DSH 地址；代理端口修改后需要重启。Grok 界面仍使用用户自己的登录会话。

如果 profile 曾安装旧三包，先从该 profile 移除它们，再安装本包。不要同时启用旧三包、本包或 ui-opt 预览版本。安装器不修改其他 profile，也不自动移除旧包。

附件资源库和历史附件专用预览仍未接入。
