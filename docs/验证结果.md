# 单包工作台验证记录

检查日期：2026-11-07。版本：dsh-plugin-workbench-suite 0.1.0。运行环境：Node.js 24.18.0、npm 11.16.0、DSH 0.2.1-rc.5。

## 包结构与入口

- 仓库根目录是唯一 npm 包，没有 workspaces 或内部 peer 依赖。
- 源码分别位于 src/sources、src/herdr、src/grok、src/settings；来源栏共享接口只在包内部使用。
- index.js 是唯一宿主入口，dist/client.js 注册唯一浏览器插件 factory。
- cordis.patch.yml 只启用一个工作台插件。

## Grok 设置与状态的浏览器回放

使用临时本机服务、真实 React 页面和模拟机器人数据，实际点击账号与会话设置、输入 Auth、保存、重新启动服务并移除配置。输入框保存后为空且保持密码样式；Auth 不出现在读取接口或浏览器 localStorage 中；无效输入保留并显示错误，未授权写入返回 401。

四种状态显示为运行中、待输入、待查看、空闲中；每个机器人仅一个标记，侧栏标记宽度均为 47 像素，蓝、橙、紫、灰配色在浏览器计算样式中各不相同。对话标题的未读状态仅显示一个待查看标记。最终回放没有页面错误。

上述状态回放使用独立预览页面与现有插件代码，没有连接用户在用的 DSH 页面或真实 Grok 账号。

## DSH 插件详情页的浏览器验收

使用本机 DSH 0.2.1-rc.5 的官方 Web 页面，在独立临时 DSH_HOME 中创建 web 模板 profile 并安装本仓库。侧栏「插件」→ 已安装插件 → 本插件详情页中直接显示配置区域，可切换工作台来源、Herdr 和 Grok bot，未打开设置弹窗。

实际验证来源标签隐藏与恢复、Herdr 三个接入字段可见、Grok Auth 的错误输入保留、模拟 Auth 保存后清空、重新进入后读取及移除。Grok 的更多菜单、账号与会话设置和 Herdr 的设置按钮都进入同一详情页。Auth 原文没有返回到读取接口或写入 localStorage，页面没有未处理错误。

临时 profile 使用模拟 Grok relay、专用 Cookie 文件和独立 Herdr 代理；没有调用真实 Grok 账号，未保存 Herdr 接入设置。浏览器和测试服务在验收后关闭。

## 自动读取的交互说明

在独立 DSH 中，通过只返回模拟登录信息的浏览器调试连接验证实际读取流程：打开页面自动检测，未找到时提示手动 Auth；点击「自动读取登录信息」后来源显示浏览器。保存手动 Auth 后，其优先关系和切换步骤可见；移除后重新读取可恢复浏览器来源。无效输入保留，保存和移除反馈显示在手动区，清除缓存保留浏览器登录信息。读取接口和 localStorage 不含 Auth 原文，页面没有未处理错误或横向溢出，卡片标题保持在内部。

此处验证的是模拟调试连接与实际插件的交互，没有访问用户浏览器或真实账号。
